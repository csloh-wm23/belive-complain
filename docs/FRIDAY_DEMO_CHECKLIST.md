## Reproduce on another computer

Before pulling an older installation, export reviewed knowledge and copy its archive plus matching recovery key to safe private storage outside the checkout. Retain that computer's own `.env`, data/database and credential key. Code updates remove the formerly tracked archive and do not carry later knowledge changes.

Install native Hermes, configure an authorised model connection, and obtain permitted knowledge files privately. Place the archive at `knowledge/team-memory.enc.json` **before** importing the matching key under **Self-learning → Team knowledge backup → Restore on another computer**. Key alone cannot restore a missing archive. Confirm restoration before these paid live rehearsals. See [private transfer instructions](SHARED_MEMORY.md).

Deliberately opt in:

```sh
python scripts/rehearse_native_support.py --run-live --phase all
python scripts/rehearse_public_review.py --run-live --capture-ui
```

Without `--run-live`, these scripts perform no live work. They use isolated labelled workspaces. The public script accepts `--review-url "INDIVIDUAL_GOOGLE_REVIEW_URL"` for a permitted source. It needs no old local case ID. Missing live content and no matching saved capture produce BLOCKED without invented reviews. Active-database model settings are used in memory, not copied into reports or the test credentials table.

Retain detailed output privately and use the private operator account for its own isolated workspace. Do not assume another computer has the same local database, credentials or case links. See [the operating guide](FYP_DEMO_GUIDE.md).
